# PART 2 — PRODUCT VISION

WALLORA is not simply a wallpaper application.

It is an AI-powered creative platform where users can discover visual content, communicate with AI, generate artwork, edit images, build projects, interact with creators, publish digital creations and monetize their work.

The product should combine the best ideas behind:

- Pinterest: visual discovery and inspiration.
- ChatGPT: conversational AI assistance.
- Canva: accessible creative tools.
- Instagram: profiles and community.
- Creative marketplaces: digital products and creator monetization.
- AI image studios: image generation and editing.
- Personalization applications: wallpapers, collections and digital aesthetics.

These are product references, not instructions to copy their branding, interfaces or proprietary designs.

## Core product promise

A user should be able to enter WALLORA with an idea and leave with something they have created, discovered, organized, shared or purchased.

Example:

A user opens WALLORA and types:

"I want to create a futuristic luxury bedroom design with black walls, golden lighting, a gaming setup and a large window overlooking Nairobi."

WALLORA AI should understand the request, help refine it, select a suitable creative tool, generate a visual concept using an available model, display the result, and allow the user to save it inside a project.

Another user might ask:

"Give me five wallpapers that match my dark minimalist phone setup."

WALLORA should understand the request and search the approved wallpaper library.

# PART 7 — NVIDIA AI INTEGRATION

NVIDIA NIM is the primary AI provider for eligible hosted model endpoints.

Do not assume every NVIDIA model supports every capability.

At the beginning of AI development:

1. Inspect NVIDIA's current model catalogue.
2. Verify hosted endpoint availability.
3. Verify request and response formats.
4. Verify free-tier limitations.
5. Verify image generation capabilities.
6. Verify supported image sizes and formats.
7. Verify commercial usage and licensing terms.
8. Document the verified models.

Official sources:

- https://build.nvidia.com/
- https://docs.api.nvidia.com/nim/
- https://developer.nvidia.com/nim

## AI provider abstraction

Implement interfaces similar to:

```ts
interface AIProvider {
  id: string;
  name: string;

  getCapabilities(): Promise<ModelCapability[]>;

  generateText(
    request: TextGenerationRequest
  ): Promise<TextGenerationResult>;

  analyzeImage?(
    request: ImageAnalysisRequest
  ): Promise<ImageAnalysisResult>;

  generateImage?(
    request: ImageGenerationRequest
  ): Promise<ImageGenerationResult>;

  getJobStatus?(
    jobId: string
  ): Promise<GenerationJobStatus>;
}
```

Use capability-based routing.

Do not assume an OpenAI-compatible endpoint supports image generation merely because it supports chat completions.

## AI capabilities

Separate these operations:

- Text conversation.
- Prompt enhancement.
- Image understanding.
- Text-to-image.
- Image-to-image.
- Embeddings.
- Content moderation.
- Image upscaling.

A provider can support some capabilities without supporting all of them.

## Free usage management

Create a configurable credit system.

Possible example:

- Free users: limited daily AI operations.
- Plus users: larger monthly allowance.
- Pro creators: higher configurable limits.

Do not hardcode prices or limits.

Use an admin-configurable entitlement system.

Reserve credits atomically before executing expensive work.

Refund or reconcile credits for failed operations.

Prevent duplicate charging during retries.

## AI chat memory

Implement:

- Conversation history.
- Conversation summaries when appropriate.
- User-configurable creative preferences.
- Project-specific context.
- User-controlled deletion.

Do not send unnecessary personal data to AI providers.
